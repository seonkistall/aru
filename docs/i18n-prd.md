## 1. 배경 & 문제 정의

아루는 카메라로 피부를 읽고 K뷰티 제품 3종 + 아침/저녁 루틴을 추천하는 웹앱이다.
제품 검증(30명 파일럿 → BD)의 다음 단계로 **외국인 사용자 검증**이 필요하지만,
전체 UI·추천 카피·동의/프라이버시 문구가 한국어 단일 언어라 외국인 테스터가
제품을 이해하고 끝까지 진행하는 것 자체가 불가능했다.

추가로 1차 다국어 릴리스(PR #32) 이후 검증 과정에서 발견된 UX 문제 4건
(설문 문구, 예산 선택지, 텍스트 오버플로, 언어 혼입 버그)과
리포트 페이지의 과밀 문제를 2차 릴리스(PR #33)에서 해결했다.

### 타깃 사용자
| 세그먼트 | 니즈 |
|---|---|
| 한국어 사용자 (기존) | 변화 없는 기존 경험 유지 |
| 영어권 테스터 | K뷰티 관심, 영문 제품명/구매 가능성 확인 |
| 일본어권 테스터 | K뷰티 최대 수출 시장, 스킨케어 용어 정확성 중요 |
| 중국어권 테스터 | 간체 중문, 크로스보더 구매 흐름 |

## 2. 목표 & 성공 지표

### 목표
1. **G1** — 외국인 테스터가 언어 장벽 없이 `홈 → 스캔/설문 → 리포트 → 케어` 전체 퍼널을 완주할 수 있다.
2. **G2** — 언어 전환이 즉각적이고(재로드 불필요), 선택이 세션 간 유지된다.
3. **G3** — 한국어 사용자 경험에 회귀(regression)가 없다.
4. **G4** — 리포트가 단계별로 소화 가능한 분량으로 나뉜다 (한 화면 5개 섹션 과밀 해소).

### 성공 지표 (파일럿 측정)
- 외국인 테스터 퍼널 완주율 (scan_started → reco_viewed) ≥ 한국어 대비 80%
- 언어 전환 후 잘못된 언어 노출 리포트 0건
- 리포트 단계 이탈 지점 데이터 확보 (funnel 이벤트 기반)

## 3. 범위

### In Scope
- 언어 4종: **한국어(기본) · English · 日本語 · 中文(간체)**
- 우측 상단 고정 언어 선택기 (전 페이지 공통)
- 사용자 대면 전 화면: 홈, 스캔(가이드·피드백·결과), 설문, 리포트, 케어, 체크인, 카드 스튜디오, 프라이버시, 에러/404
- 데이터 카피: 제품 브랜드·제품명(공식 로마자), 성분명·설명, 하이라이트, 피부타입·고민·카테고리 값
- LLM 생성 추천 이유(`/api/reason`)의 선택 언어 생성
- 설문 개선: 화해 기준 문구 삭제, 예산 5단계(1/2/3/4만원·5만원 이상)
- 리포트 3단계 플로우 분리
- 언어 혼입 버그 수정 (영속 데이터 한국어 원본화)

### Out of Scope (의도적 제외)
- 내부 연구/운영 대시보드 (`/ops`, `/eval`, `/pilot`) — 운영자용, 한국어 유지
- 리인게이지 **이메일** 본문 — 서버 크론 발송이라 발송 시점에 클라이언트 언어를 모름. 한국어 유지
- 서버 메타데이터(`<title>` 등) 언어별 분기 — SSR은 항상 한국어, SEO 다국어화는 후속 과제
- LLM 비전 분석(`/api/analyze`) narrative의 다국어 생성 — 효능표현 컴플라이언스 필터(`efficacyClean`)가 한국어 기반이라 한국어 생성 유지, 비한국어 모드는 템플릿 재조립으로 대체 (스펙 문서 §6 참조)
- 통화 환산 — 가격은 KRW(₩) 고정 표기

## 5. 비기능 요구사항

- **컴플라이언스**: 효능·치료 표현 금지 원칙이 전 언어에 적용. LLM 출력은 `efficacyClean()` 게이트 유지, 시스템 프롬프트에 언어별 동등 표현 금지 명시
- **프라이버시**: 동의 2분리(AI 분석 전송 / 학습용 크롭 저장) 문구가 4개 언어에서 동일한 의미로 정확히 전달. 동의 감사 기록은 한국어 원문 버전 기준 유지
- **성능**: 사전 3개(en/ja/zh) 번들 포함 — 정적 import, 페이지당 추가 네트워크 요청 0. 언어 전환 = 클라이언트 리마운트(수십 ms)
- **품질 게이트**: `npm run smoke`(lint+build+라우트), `npm test`(95 tests), 사전 커버리지 스크립트(추출 msgid 대비 누락 0)
